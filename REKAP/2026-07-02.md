## Backend (siamin1.0)

### 1. Fix: Daftar TPK Tidak Tampil di Formulir Frontend

**Masalah:** Endpoint `GET /api/v1/kegiatan/all` (Dashboard) hanya mengembalikan satu lokasi TPK via subquery `LIMIT 1`. Frontend yang memanggil endpoint ini hanya mendapat satu lokasi, bukan array `daftar_tpk`.

| File | Perubahan |
|------|-----------|
| `DashboardService.php` | Tambah `->with('daftarTpk')` agar eager-load semua TPK per kegiatan |
| `DashboardKegiatanResource.php` | Tambah field `daftar_tpk` via `$this->whenLoaded('daftarTpk')` |

### 2. Resource URL & Metadata pada Dashboard API

**Masalah:** Endpoint dashboard tidak mengembalikan field `dokumentasi_url`, `materi_url`, `panduan_url`, `laporan_url`, `surat_menyurat_url`, `metode_pelaksanaan`, `metode_pembayaran`, `deskripsi`, `rincian_kegiatan`. Modal detail di frontend tidak bisa menampilkan data ini.

| File | Perubahan |
|------|-----------|
| `DashboardService.php` | Tambah kolom berikut ke `$selectColumns`: `metode_pelaksanaan`, `metode_pembayaran`, `deskripsi`, `rincian_kegiatan`, `dokumentasi_url`, `materi_url`, `panduan_url`, `laporan_url`, `surat_menyurat_url` |
| `DashboardKegiatanResource.php` | Tambah field yang sama ke `toArray()` |

## Catatan Teknis

- `DashboardService` menggunakan `leftJoin` + `select` + `with('daftarTpk')`. Eager-load berjalan sebagai query terpisah, tidak konflik dengan join.
- `DashboardKegiatanResource` menggunakan `whenLoaded('daftarTpk')` — mengembalikan `null` jika relasi tidak di-load, array jika di-load.
- Frontend `kegiatanLocation.js` sudah menangani `daftar_tpk` sebagai kandidat utama (prioritas pertama), sehingga tidak perlu perubahan.
- QR code di Kegiatan.vue menggunakan `activityQrCodeMap` dengan key = URL, di-generate otomatis via watcher pada `activityLinks`.
